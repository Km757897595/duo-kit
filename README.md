# Duo Kit

**简体中文** | [English](README.en.md)

**让 Codex 负责规划与验收，让 Cursor 或另一个 Codex 聊天负责执行。**

Duo Kit 是一套面向 macOS 的轻量 AI 编程协作工具包，由 Bash 脚本、指令规则和项目模板组成。它用任务单明确改动范围、禁区和验收标准，通过项目文件与 Git 衔接 Codex 和 Cursor 的工作。

平时直接让 Codex 完成工作；需要分工时，在消息中加入 `/duo`，再把生成的任务单交给 Cursor 或另一个 Codex 聊天。

> 这是文件驱动的协作约定，需要你手动在两个工具之间交接；规则用于约束 Agent 的工作方式，不是权限隔离或自动调度系统。

## 为什么用 Duo Kit

- **按需协作**：默认由 Codex 直接完成任务，只有包含 `/duo` 的消息才进入协作模式。
- **任务有边界**：每张任务单列出目标、允许改动文件、禁区与验收命令。
- **交接可追踪**：计划、任务状态和范围外发现保存在 `.work/`，不依赖两个工具共享聊天记录。
- **执行后再验收**：突击手自测后提交待验收，Codex 检查差异并亲自运行验收命令。
- **可重复安装**：全局指令按标记块更新，项目初始化跳过已有文件。

## 使用前准备

- macOS 与 Bash；脚本使用常见 Unix 命令，`pbcopy` 用于复制规则到剪贴板。
- 可用的 Codex 环境；使用 Cursor 执行时，还需自行安装与配置 Cursor。
- 目标项目建议使用 Git，以便验收时检查 `git diff`。

工具包无需安装额外包依赖。当前以 macOS 为使用环境，其他系统的兼容性未验证。

## 快速开始

### 1. 安装全局规则

下载或克隆本仓库，在解压或克隆得到的 `duo-kit` 目录中运行：

```bash
chmod +x bin/duo-install bin/duo-init
./bin/duo-install
```

安装脚本会执行以下操作：

| 位置 | 操作 |
| --- | --- |
| `~/.codex/AGENTS.md` | 写入或更新 `DUO-KIT` 标记块，保留块外内容 |
| `~/.codex/prompts/duo.md` | 不存在时复制命令模板；已存在时跳过，不覆盖 |
| 系统剪贴板 | 使用 `pbcopy` 复制 Cursor User Rules；不可用时提示手动复制 |

随后打开 Cursor 的规则设置，在 User Rules 中粘贴规则。也可以手动复制 [global/cursor-user-rules.md](global/cursor-user-rules.md) 的内容。

将当前工具包的 `bin` 目录加入 PATH。在 **duo-kit 根目录**执行：

```bash
echo "export PATH=\"$(pwd)/bin:\$PATH\"" >> ~/.zshrc
source ~/.zshrc
command -v duo-init
```

最后一条命令应输出 `duo-init` 的路径。使用其他 Shell 时，请调整对应配置文件；移动工具包后，也需要更新 PATH。

### 2. 初始化目标项目

进入你要开发的项目目录，而不是工具包目录：

```bash
cd /你的项目路径
duo-init
```

初始化会生成：

```text
你的项目/
├── AGENTS.md                  # 两个工具共同遵守的项目规范
├── .cursor/
│   └── rules/
│       └── main.mdc            # 引导 Cursor 遵守项目规范
└── .work/
    ├── plan.md                # 目标、架构约束、禁区与进度
    ├── notes.md               # 执行过程中发现的范围外问题
    └── tasks/
        └── 000-template.md    # 任务单模板
```

初始化后，先补全 `AGENTS.md` 中的项目简介、安装依赖、构建、测试、Lint 命令与代码规范，并在 `.work/plan.md` 中填写目标和架构约束。

**已有同名文件会被跳过，不会自动合并规则。** 如果项目原来已有 `AGENTS.md` 或 `.cursor/rules/main.mdc`，请对照 [template/](template/) 手动合并所需内容。

建议将这些协作文件纳入目标项目的版本控制，方便追踪任务和交接记录。

> 当前内置规则、项目模板和脚本输出为中文。英文 README 提供使用说明，不改变安装内容的语言；使用内置协议时，请保留文档中的中文验收、状态关键词及任务状态标签。

## 两种工作模式

| 发给 Codex 的消息 | 行为 |
| --- | --- |
| `帮我修复登录失败的问题` | 默认模式：Codex 直接改代码、跑测试，不创建任务单 |
| `/duo 加登录功能` | 协作模式：Codex 规划并在 `.work/tasks/` 写任务单，交给 Cursor 或另一个 Codex 聊天实现 |
| `/duo 执行 003` | Codex 担任突击手，执行 003 号任务单，自测通过后置为「待验收」 |
| `/duo 验收 003` | Codex 检查并验收 003 号任务单 |
| `/duo 状态` | Codex 汇总任务编号、标题、状态，并给出下一步建议 |

协作模式只对包含 `/duo` 的当前消息生效，后续消息仍需显式携带触发词。

### 一次完整的协作

**第一步：让 Codex 拆任务。** 在 Codex 中发送：

```text
/duo 为登录接口增加参数校验，遵守现有接口格式，并补充测试。
```

Codex 读取项目规范、计划和备注，按模板创建任务单，例如 `.work/tasks/001-登录参数校验.md`，列出具体改动范围、行为验收场景和可执行的验收命令。

**第二步：让 Cursor 或 Codex 执行。** 在同一个项目中打开 Cursor，将实际生成的任务单路径交给 Agent：

```text
执行 .work/tasks/001-登录参数校验.md
```

也可以在另一个 Codex 聊天中打开同一项目，发送：

```text
/duo 执行 001
```

突击手先记录基础提交和执行前已有改动，将任务改为「进行中」，在允许范围内实现并运行验收命令、逐项验证验收场景。通过后记录交接代码版本并改为「待验收」；范围外发现写入 `.work/notes.md`。

**第三步：让 Codex 验收。** 回到 Codex 发送：

```text
/duo 验收 001
```

Codex 先核对交接代码版本，检查已提交、暂存、未暂存及新增文件的改动，再核对文件范围和架构约束，亲自运行验收命令并逐项验证场景。通过后标记「完成」并更新计划；不通过则退回「进行中」，在备注中写明问题，再交给突击手修正。

```text
待办 → 进行中 → 待验收 → 完成
         ↑        │
         └─验收不通过─┘
```

只有架构师验收后才能把任务置为「完成」，突击手不得在执行流程中自行验收。建议每个任务使用独立分支或 worktree，便于核对改动范围。

## 任务单约定

每个任务一个文件，命名为 `NNN-简短名称.md`，编号三位递增。`000-template.md` 用作模板。

| 字段 | 内容要求 |
| --- | --- |
| 目标 | 描述一个明确、可验收的小任务 |
| 允许改动文件 | 列出具体文件路径或目录 |
| 禁区 | 明确不能触碰的文件或行为 |
| 验收场景 | 输入或操作、可观察的预期结果，覆盖正常、异常和必要回归 |
| 验收命令 | 可直接执行，并有明确通过标准 |
| 代码版本 | 工作目录、分支、基础提交、执行前已有改动、交接 HEAD 及未提交代码的 SHA-256/删除状态 |
| 状态 | 待办、进行中、待验收、完成四选一 |
| 备注 | 记录实现说明、验收结果或退回原因 |

完整格式见 [任务单模板](template/.work/tasks/000-template.md)。

### 代码版本与验收证据

- 首次执行前记录工作目录、分支、基础提交和已有改动；继续执行时保留原基础。交接时记录当前 HEAD、本任务提交(如有)和未提交代码文件的状态及 SHA-256，不要求自动提交。
- 验收时使用 `git diff <基础提交> <交接HEAD>` 检查已提交改动(替换为实际提交)，同时检查 `git diff --cached`、`git diff` 和 `git status --short --untracked-files=all`，并读取新增文件。单独运行默认 `git diff` 会漏掉已提交、已暂存或未跟踪的内容。
- 比较执行前记录，区分本任务与既有改动。交接后代码发生变化或版本无法确认时，先补齐证据或重新交接，不直接沿用旧验收结果。
- 无 Git 或尚无初始提交时，按协议记录执行前文件清单、相关已有文件 SHA-256，以及交接时的差异、结果文件 SHA-256/删除状态；不使用不存在的提交间比较。
- 命令通过还需满足验收场景。例如登录校验任务，应检查“缺少密码返回约定错误”“正常凭据仍可登录”，并在备注记录实际结果。仅构建通过不能替代行为验证。

## 更新与移除

更新本地工具包后，在工具包目录运行：

```bash
./bin/duo-install --update
```

再到每个已初始化的目标项目目录运行：

```bash
duo-init --update
```

| 命令 | 更新行为 |
| --- | --- |
| `duo-install` | 更新全局 `DUO-KIT` 标记块；已有提示词文件仍跳过 |
| `duo-install --update` | 更新全局标记块，并备份后替换已有 `~/.codex/prompts/duo.md` |
| `duo-init` | 只创建缺失文件，已有文件跳过 |
| `duo-init --update` | 更新项目 `AGENTS.md` 的协作标记块，并备份后替换 `.cursor/rules/main.mdc`；创建缺失的模板文件 |

- 每次实际修改已有文件前，在同目录生成 `原文件名.duo-backup.随机后缀` 备份；内容相同则跳过，不重复备份。可手动从备份恢复；备份可能包含个人规范，请按项目需要加入 `.gitignore`。
- 项目简介、构建命令和标记块外的自定义规范保留；`.work/` 中已有的计划、备注、任务及任务模板不覆盖。
- 更新后请对照新的 [任务单模板](template/.work/tasks/000-template.md)，手动给已有模板和待执行任务补充「验收场景」「代码版本」；历史基础不明时记录现状并明确重新交接，不编造旧记录。
- 旧版项目没有标记块时，更新脚本会替换标题为 `## 协作协议(架构师 + 突击手)` 的章节，保留后续同级或更高级标题开始的内容；该章节内的自定义内容请从备份手动合并。不存在该章节时，追加协作标记块。
- 自定义规则请放在标记块外。提示词文件和 Cursor 项目规则属于整文件替换，其中的自定义修改需从备份手动合并。Cursor User Rules 仍需手动粘贴更新，安装脚本会复制到剪贴板。
- 标记缺失配对或重复时，脚本报错并保留该规则文件，需修复标记后重试。
- 两个脚本均支持 `--help`；更新使用当前本地工具包内容，不会自动拉取仓库。

如需移除：

1. 在 `~/.codex/AGENTS.md` 中删除 `<!-- DUO-KIT:BEGIN -->` 至 `<!-- DUO-KIT:END -->` 的整段内容，保留其他指令。
2. 删除由本工具安装的 `~/.codex/prompts/duo.md`，并移除 Cursor User Rules 中的 Duo Kit 规则。
3. 删除 Shell 配置中添加的 PATH 行。
4. 按需清理目标项目的协作文件；已有项目规范和任务记录请先备份或手动合并。

## 常见问题

### 提示找不到 `duo-init`

确认 PATH 指向工具包的实际 `bin` 目录，并重新加载 Shell 配置。也可以使用 `duo-init` 的绝对路径，在目标项目目录中运行它。

### 为什么初始化后没有出现协作规则？

`duo-init` 会跳过所有已存在的同名文件。使用 `duo-init --update` 更新协作规则；普通重复初始化仍不会替换旧规则。

### `/duo` 是必须注册的斜杠命令吗？

核心约定是消息中的 `/duo` 触发词，由安装的指令规则解释。工具包还提供一份使用 `$ARGUMENTS` 的 Codex CLI 自定义提示词模板，并尝试安装到 `~/.codex/prompts/duo.md`；是否将其识别为菜单命令，取决于所用客户端和版本。

即使客户端没有对应命令入口，也可以直接在消息中写 `/duo 需求`，让 Codex 按项目规则处理。

### 两个工具会自动互相调用吗？

不会。你需要手动把任务单路径交给 Cursor，或在另一个 Codex 聊天发送 `/duo 执行 <编号>`，再回到架构师聊天发起验收。交接依据是 `.work/` 文件和 Git 改动。
