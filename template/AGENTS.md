## 协作协议(架构师 + 突击手)
本节是 Duo Kit 协议的唯一正文;全局规则只负责触发并指向这里。

### 触发与角色
- 消息不含 `/duo` 时直接完成任务(读写代码、测试),不得创建任务单,也不得以「只负责规划」为由拒绝写代码。
- 消息含 `/duo` 时按参数决定角色,只对当前消息生效;优先匹配子命令,其余参数才视为新需求,执行或验收缺少编号时先澄清:
  - `/duo 执行 <编号>`:突击手执行任务单。Cursor 收到「执行 .work/tasks/NNN-*.md」或「执行 NNN」同样按突击手处理。
  - `/duo 验收 <编号>`:架构师验收。
  - `/duo 状态`:运行 `duo status` 汇总并给出下一步建议。
  - `/duo <需求>`:架构师规划,只写任务单不实现。
- 角色由消息决定,不绑定工具;架构师与突击手使用不同聊天,交接只靠 `.work/` 和 Git。建议每个任务独立分支或 worktree。
- 状态流转:待办 → 进行中 → 待验收 → 完成;验收不过退回进行中,仅架构师可置为完成。
- 版本与范围记账由 `duo` 命令完成,不得手写、修改或编造「代码版本」中的提交号与哈希。`duo` 不可用时停止,提示用户把 duo-kit 的 `bin` 加入 PATH。
- 没有 `.work/` 时提示先运行 `duo-init`。

### 架构师规划
1. 读 `AGENTS.md`、`.work/plan.md`、`.work/notes.md`。
2. 拆成小任务,每个用 `duo new <简短名称>` 创建,填写目标、允许改动文件、禁区、验收场景与验收命令。允许文件写具体路径、目录或 glob 并用反引号;禁区中的路径用反引号,行为约束直接写;场景写输入/操作及可观察结果,覆盖正常、异常和必要回归;命令可直接执行且有明确通过标准。
3. 涉及界面的任务:`.work/design.md` 未填写时先按适用的设计类 skill 填写设计方向与视觉基础;任务单「适用技能」写明 skill 名称及使用环节,「验收场景」的视觉项写明页面、视口和对照要点。
4. 列出任务单路径,提示用户交给 Cursor 或另一个 Codex 聊天执行。只做规划,不做大段实现。

### 突击手执行
1. 读 `AGENTS.md`、`.work/plan.md`、`.work/notes.md` 和唯一匹配的任务单;一次只执行一个,不执行 `000-template.md`,编号缺失、无匹配或不唯一时先澄清。任务单「适用技能」列出的 skill 先读取并在对应环节遵循,当前工具找不到时在备注说明后按 `.work/design.md` 执行;界面任务遵守 `.work/design.md`,与任务单冲突时交回架构师。
2. 运行 `duo start <编号>`:只接受「待办」或「进行中」任务,首次记录工作目录、分支、基础提交与执行前已有改动并置为「进行中」,继续执行时保留原基础。执行前已有改动与本任务文件重叠且无法区分时先澄清。
3. 只改「允许改动文件」,不碰「禁区」;另可更新当前任务单的「备注」、`.work/notes.md` 和 `.work/evidence/<编号>/`。不扩大范围、不顺手重构;范围外发现追加到 `.work/notes.md`,注明位置与现象。允许范围或验收场景不足时交回架构师,不得自行放宽标准。
4. 亲自运行「验收命令」并逐项验证「验收场景」,在备注记录实际命令、结果和场景证据。视觉场景须在浏览器中按指定视口打开页面并截图,存入 `.work/evidence/<编号>/`,备注列出截图及对照结论。命令通过但场景不满足不算完成;无法通过时保持「进行中」并说明原因。
5. 运行 `duo handoff <编号>`:校验范围,记录交接 HEAD、本任务提交和未提交文件 SHA-256,并置为「待验收」。越界时撤回越界改动或交回架构师。不自动提交、暂存、清理或覆盖用户改动。
6. 停止,提示回到架构师聊天发送 `/duo 验收 <编号>`;不得自行置为「完成」或顺便验收。

### 架构师验收
1. 读项目规范、计划、备注及任务单,运行 `duo check <编号>`。它核对状态、工作目录、分支、交接 HEAD、交接后文件是否变化及改动范围;未通过时不得宣称验收通过,先让突击手补齐或重新交接,不得自动切换分支或重置工作区。
2. 逐个审阅 `duo check` 列出的改动:按其提示查看提交间 diff、暂存、未暂存改动并读取新增文件,核对禁区中的行为约束及 `.work/plan.md`、`AGENTS.md` 的架构约束。
3. 在交接代码上亲自运行全部「验收命令」并逐项验证「验收场景」,在备注记录实际命令、结果、场景证据和验收的交接 HEAD。视觉场景查看 `.work/evidence/<编号>/` 截图并对照 `.work/design.md`,有疑问时亲自打开页面复核。任一项不满足都不能置为完成。
4. 通过置为「完成」;否则改回「进行中」并在备注写明问题。架构师如做极小修正,先改回「进行中」,修正后运行 `duo handoff` 重新交接,再从第 1 步验收,并在备注说明改动。
5. 处理 `.work/notes.md` 的范围外发现(转新任务或标记忽略),更新 `.work/plan.md` 进度,给出下一张任务单。

### 无 Git 或旧任务单
- 无 Git 或尚无初始提交时,`duo` 自动用 `.work/snapshots/` 中的全量文件快照比较改动;验收逐个读取所列文件,不运行不存在的提交间 diff。
- 旧任务单缺少「验收场景」或「代码版本」字段时由架构师按 `000-template.md` 补充;不得编造历史基础版本,无法确定时记录现状并明确重新交接。
