## 协作协议(架构师 + 突击手)
- **触发词 `/duo`**:默认情况下 Codex 自己直接完成任务(读写代码、测试),不创建任务单。仅当用户消息含 `/duo` 才进入协作模式:
  - `/duo 执行 <编号>`:Codex 担任突击手,执行已有任务单。优先匹配执行、验收、状态子命令,其余参数才作为新需求;缺少编号时先澄清。
  - `/duo <需求>`:Codex 担任架构师,只规划不实现,写任务单到 `.work/tasks/`,然后提示用户让 Cursor 或另一个 Codex 聊天执行。
  - `/duo 验收 <编号>`:Codex 验收指定任务单。
  - `/duo 状态`:Codex 汇总所有任务单状态。
  - 未出现 `/duo` 时,不得创建任务单,也不得拒绝写代码。
- 角色由当前消息决定,不与工具绑定。架构师与突击手建议使用不同聊天,通过文件交接。
- 架构师(Codex):只规划与验收。写任务单到 `.work/tasks/`,验收时读 `git diff`,核对范围、架构约束和验收命令。
- 突击手(Cursor 或 Codex):先读 `AGENTS.md`、`.work/plan.md`、`.work/notes.md` 和指定任务单;一次只执行一个任务单,编号必须唯一,不执行 `000-template.md`。任务不存在、匹配不唯一或编号缺失时先澄清;没有 `.work/` 时提示先运行 `duo-init`。
- 只执行「待办」或「进行中」任务,开始置「进行中」;「待验收」或「完成」不重复执行,提示验收或明确重新打开。只改「允许改动文件」及当前任务单的状态、备注和 `.work/notes.md`,不碰「禁区」;范围外发现写入备注文件,不自行处理。
- 改完亲自跑验收命令,在任务备注记录实际命令与结果。自测通过改为「待验收」并停止,提示回到架构师聊天发送 `/duo 验收 <编号>`;无法通过保持「进行中」并说明原因。突击手不得自行置「完成」或顺便验收。
- 状态流转:待办 → 进行中 → 待验收 → 完成(仅架构师可置为完成;验收不过则退回进行中)。
- 交接只靠 `.work/` 文件和 git,不依赖聊天记录。
- 每个任务建议独立分支或 worktree。
